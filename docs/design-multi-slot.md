# 调研：一个元件占用多个格子（拆格存放）

> 场景（用户原话）：**有时候一个格子装不下需要拆成几个，但是相同的东西写两个一样的又不太好。**
> 明确排除：**不要单纯地"把小格子变成大格子"**（网格合并成区域）。
> 本文只做方案调研与取舍，选定后再进入实现。

## 1. 问题拆解

同一个物料被拆到多个格子，本质是**"一个物料 ↔ 多个物理位置"**的映射问题。需要同时满足：

| 维度 | 要求 |
| --- | --- |
| 库存 | 一个物料一个库存总数（拆成两行会各算各的，BOM 会算少、盘点会算错） |
| 检索 | 搜一次只出一条（拆成两行会出现重复结果、标签/卡面设置也要维护两份） |
| BOM / 引导取料 | 一个物料只出一步，取料时去哪一格取要说得清（多格都可以取） |
| 灯带 | 拆开的几个格子都要能点亮（引导时用户可能在任意一格取） |
| 布局变更 | 改层数/行列后，被拆的格子不能把数据搞丢（这是"合并成大格子"方案最怕的） |
| 维护成本 | 改一次名称/封装/标签，不要改 N 遍 |

## 2. 候选方案

### 方案 A：多槽位绑定（一个元件挂多个格子）★ 推荐

元件仍是**一行记录**（库存、标签、卡面设置都只有一份），额外占用的格子记在从表里：

```
components            component_slots
-----------           -------------------------------------------
id / name / qty       id / component_id(FK,CASCADE)
zone, layer, slot  ← 主格   zone / layer / slot   ← 附加格
                          UNIQUE(zone, layer, slot)  一个格子只能属于一个元件
```

- **主格**仍是 `components.zone/layer/slot` → 现有检索、BOM、引导、游离判定的代码全部不用改；
- 从表为空 = 现在的行为（迁移成本≈0，老库不需要改数据）；
- 卡片：主格正常显示，右上角多一个「3 格」小标；附加格显示成**共用卡**（同一张卡片的淡化版 + 链接标 + 指向主格的位置），点它打开的是同一个元件；
- 引导取料：该物料的**所有格子一起点亮**，取哪一格都算；
- 布局缩容：附加格超出网格时，跟游离元件一起提示、一起"搬回空格"；
- 编辑入口：元件窗口里加一块「占用格子」——格子列表（chip，可删）+ 一个"添加格子"的空位下拉；网格上不引入新模式，避免可发现性问题；
- 迁移助手（可选）：一键找出 `名称+标称值+封装` 完全相同的元件，合并成一条并把数量相加、旧格变附加格。

代价：新增一张表 + 一条迁移 + 编辑窗口一块 UI + 引导多条点灯 + 游离判定扩展；约 1 天后端 + 1~2 天前端。

### 方案 B：同物料多批次（分组，各自记数量）

保留多行，新增 `group_id` + `is_primary`，检索/BOM 按组聚合（库存求和）。

- 适合"每格确实各自有独立数量"的场景（一格已拆封、一格整包）；
- 但共享属性（名称/封装/标签/卡面）要**组级编辑**才不会改 N 遍，等于要在 A 之上再加一层；
- BOM 取料要决定从哪一行扣（可自动选数量最多的那行）。

结论：只有在"每格数量必须分开记"时才值得；否则成本高于 A 而收益相同。可作为 A 的第二阶段（`component_slots.quantity` 可选列）。

### 方案 C：网格区域合并（小格并成大格）

像表格合并单元格那样，把相邻几格并成一个矩形大格。

- 视觉上最接近"一个格子装不下"，适合放开发板、电池盒这类**大件**；
- 致命点：布局是可调的（每区层/行/列都能改），矩形区域在行列变化后必然失效，需要一套"修复/自动拆分"逻辑；
- 灯带是按槽位顺序编号的，合并后灯与格的对应关系要重新定义；
- 与"拆开存放"这个需求其实不是一回事：需求是**同一物料分散在多格**，不是**一个格子物理变大**。

结论：不作为主方案。它的价值在展示层——可以作为 A 的**展示变体**：把相邻的关联格渲染成一张跨格大卡（数据仍是 A 的模型），想要"大格子"的观感时再开。

### 方案 D：只加"容量/溢出"字段

一格仍是一行，只加 `capacity`，超了提示"建议拆格"。不解决"拆到哪、怎么算总数"，只解决提醒。可作为 A 的附带字段。

## 3. 对比

| | A 多槽位 | B 多批次分组 | C 合并格 | D 容量提示 |
| --- | --- | --- | --- | --- |
| 库存一个总数 | ✅ | 需聚合 | ✅ | ✅ |
| 检索不重复 | ✅ | 需聚合 | ✅ | ✅ |
| 每格独立数量 | ➖（可后加） | ✅ | ✅ | ✅ |
| 布局变更安全 | ✅ | ✅ | ❌ | ✅ |
| 改动量 | 中 | 中大 | 大 | 小 |
| 解决本需求 | ✅ | ✅ | ❌（不是一回事） | ❌ |

## 4. 建议

1. **先做 A**（多槽位绑定）+ 迁移助手（把已存在的重复元件合并）；
2. 需要"看着像大格子"时，再加 A 的跨格展示形态（方案 C 的观感，不含 C 的数据结构）；
3. 只有在确实需要"每格各自记数量"时，再给 `component_slots` 加 `quantity`（B 的收益，A 的结构）。
